# Product brief

## What this is

**THE UNORTHODOX PATH** — the personal portfolio of an AI/ML engineer and software developer:
a single home page plus one case-study page per project.

## Who it is for

| Audience | What they need within a minute |
| --- | --- |
| Technical recruiters, hiring managers | Role, evidence of real projects, a way to make contact |
| Engineering teams | Technical depth and judgement, shown in the case studies and the build itself |
| Freelance clients | Confidence in competence and design quality |

## What it must communicate

- Technical depth without unnecessary complexity.
- Individuality without losing professionalism.
- Quiet confidence, discipline, progression, craft.

## Identity

Murim and manhwa inform the art direction — ink and paper, mountain silhouettes, negative
space, a deliberate path — but are never the literal subject. The recurring symbol is the
Divergence: a straight path and one stroke that leaves it.

## What is built

| # | Section / route | Anchor or path | Content |
| --- | --- | --- | --- |
| 01 | The Arrival — hero | `/` | The gust, the name, role, statement, two actions, the seal |
| 02 | The Path — engineering approach | `/#approach` | Five principles, each tied to a project |
| 03 | The Archive — selected work | `/#work` | Three project discoveries linking to case studies |
| 04 | The Disciplines — technical capabilities | `/#capabilities` | Five hanging scrolls, each item linked to the work that used it |
| 05 | The Record — professional profile | `/#profile` | GitHub and LinkedIn; résumé when one exists |
| 06 | The Destination — contact | `/#contact` | One primary action to LinkedIn |
| — | Case studies | `/work/[slug]` ×3 | Problem, flow schematic, architecture, decisions, evaluation, limits, stack |
| — | Not found | any unknown URL | Way back to the start and the work |

The approach now precedes the work, following the journey the owner described; the hero's
primary action still goes straight to the work.

## Principles that shaped the content

- Every claim traces to source code or project documentation (`CONTENT_INVENTORY.md`).
- No metrics, roles, employers or dates are stated, because none could be verified.
- Each case study ends with its limitations. Candour is part of the pitch.

## Open decisions for the owner

- Confirm the displayed name and LinkedIn URL.
- Whether to publish an email and a résumé.
- Whether the ECHOSS project may be shown.
- Domain and hosting. Nothing is deployed.
